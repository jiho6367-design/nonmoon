## HTTP·저장·백업 시나리오

다음 영역을 21개의 HTTP 테스트에서 확인했습니다. 정확한 테스트 이름과 단언은 `tests/api.test.js`가 기준이며 각 테스트 안에 복수의 요청·성공·실패 조건을 확인합니다.

- 회원가입·로그인·로그아웃, 비밀번호 저장 형태와 출처 검사
- 계정 두 개 사이의 팀·논문·카드·요약·PDF 조회와 변경 차단
- 소유자의 팀원 추가·제외, 제외 직후 접근 차단
- 잘못된 파일·파일 누락·손상 PDF·용량 초과 거부와 인증된 원문 제공
- 카드 CRUD, 독립 필터, 사용자별 카드·논문 북마크
- 논문별 요약 범위와 외부 호출 없는 원문 발췌, 직접 요약 작성
- 재시작 후 자료 유지, 논문 삭제 연쇄 처리, 비밀 정보를 제외한 내보내기
- 잘못된 입력의 일관된 오류, 자료 ID 변경 차단, 실패한 수정의 원래 값 유지
- 로그인 시 기존 세션 무효화와 재사용 차단
- 체험 공간 분리 및 가공 비밀번호 로그인 차단
- 본문 없는 PDF 오류
- 외부 공급자 오류·빈 응답·민감 정보가 저장 요약이나 응답에 섞이지 않음
- API 키 누락 시 외부 요청 없이 명확한 오류
- 외부 응답 대기 중 멤버십이 제거되면 저장 전 다시 차단
- 잘못된 JSON 및 경로 탐색으로 서버·DB 파일을 읽지 못함
- 소유자만 팀 삭제 가능, 관련 자료 정리 및 다른 팀·계정 보존

`tests/backup.test.js`의 추가 테스트 1개에서 종료된 앱의 백업으로 계정·세션·논문·원본 PDF를 함께 복원하고 실제 API 요청으로 확인했습니다.

## 브라우저 시나리오

| 시나리오 | 확인 내용 |

| 체험 전체 흐름 | 카드 작성·수정·북마크, 발췌/직접 요약, 내보내기, 새로고침 유지, 로그아웃 |
| 실제 계정과 업로드 | 팀 생성, 잘못된 파일 거부, 한국어 파일명 PDF 업로드, 정보 수정·삭제 |
| 검색과 장애 | 필터 초기화, 503 응답이 빈 결과로 숨겨지지 않음 |
| 모바일 | 390×844 화면 가로 넘침, 상세 화면, 모달, Escape 닫기 |
| 실제 PDF 리더 | canvas 렌더링, 본문 확인, 다음 페이지, 카드 출처 페이지 이동 |
| 팀 관리 | 가입한 동료 추가·제외, 팀 삭제, 새로고침 후 상태 |

자동 접근성 검사에서 발견된 위반은 없었습니다. 이는 전체 WCAG 인증이나 모든 보조 기술의 수동 검사 결과를 의미하지 않습니다. `docs/images/`의 화면은 실제 실행 앱에서 자체 제작 체험 자료로 촬영했습니다.

## 검사 중 발견하고 고친 문제

- 첫 화면 검사에서 글자 대비 부족을 발견했습니다. 낮은 대비 색상을 조정한 뒤 네 화면의 자동 접근성 검사를 다시 통과했습니다.
- 내장 PDF 뷰어에 의존하는 방식이 테스트 브라우저에서 원문을 안정적으로 표시하지 못했습니다. PDF.js canvas 리더와 페이지 본문 확인 기능으로 교체하고 실제 2쪽 PDF로 렌더링·이동을 확인했습니다.
- 카드 출처 이동 버튼의 표기를 논문 제목에만 의존하던 방식에서 페이지 번호를 포함하도록 수정했습니다.
- 마지막 형식 검사에서 `tests/api.test.js`의 스타일 차이를 발견해 정리하고 검사 통과를 확인했습니다.
- PDF 리더를 필요할 때 불러오도록 분리한 뒤 초기 번들 크기 경고 없이 빌드했습니다. 성능 향상 비율은 측정하지 않았습니다.

## 실행 명령과 환경 차이

```bash
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run format:check
npm audit --omit=dev
```

이번 실행 환경에서는 Playwright 기본 Chromium 다운로드의 ZIP 오류가 발생했습니다. 별도 임시 디렉터리에 준비한 Chromium 153.0.8010.0 실행 파일을 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정해 10개 시나리오를 검증했습니다. 앱 의존성에는 이 임시 브라우저 패키지를 추가하지 않았습니다. 일반 환경에서는 Playwright 제공 브라우저를 설치해 재현할 수 있으며, 여기서는 그 기본 브라우저 버전의 실행까지 검증한 것은 아닙니다.

## PDF 불러오기 후속 수정 · 2026-10-11

- 사용자에게 PDF를 불러오지 못한다는 오류가 보고되었다. 사용자 노트북의 내부 오류 및 문제 PDF 원본은 확보하지 못해 그 환경의 단일 원인을 확정하지 않았다.
- 최신 URL·Promise 기능이 없는 브라우저 환경을 모의했을 때 기존 리더가 실패하는 문제를 재현했다. PDF.js의 호환성 빌드와 일치하는 worker로 전환한 뒤 같은 조건에서 실제 PDF 표시·본문 확인을 통과했다.
- 인증된 파일을 먼저 가져와 HTTP 상태와 PDF 헤더를 검사한 다음 바이트 데이터로 리더에 전달한다. 동기 읽기 오류도 처리하며 30초 제한과 화면 전환 시 취소를 적용했다.
- 로그인 만료, 권한, 파일 없음, PDF 이외의 응답, 읽기 오류를 구분하고 다시 불러오기 버튼을 추가했다.
- 브라우저 테스트 3개를 추가했다. 누락된 최신 API, 404 이후 재시도, 401 및 HTML 응답 구분을 포함하여 전체 10개가 통과했다. production 빌드와 형식 검사도 통과했다. 이번 변경은 화면에 한정되며 서버·저장 계약은 변경하지 않았다.

## 남은 한계

- 기본 요약은 최대 6개 페이지의 원문 발췌이며 연구 전체의 의미나 결론을 보장하지 않습니다. OCR·의미 검색은 포함하지 않습니다.
- 선택 OpenAI 경로는 모의 응답으로 성공·실패 계약을 확인했습니다. 실제 유료 API의 연결·모델 응답 품질은 확인하지 않았습니다.
- 자체 제작 PDF와 명시된 오류 파일로 검사했습니다. 모든 PDF 형식·언어·대용량 파일 지원을 보증하지 않습니다. 현재 제한은 20MB·300쪽입니다.
- 로컬 앱과 단일 프로세스 SQLite 구조를 검증했습니다. 운영 배포·HTTPS 구성·대규모 부하·전체 침투 테스트·다중 서버 운영은 포함하지 않습니다.
- 기존 MySQL·JSON 데이터의 자동 이전은 포함하지 않습니다. 체험 자료는 실제 학술 근거로 사용하면 안 됩니다.
